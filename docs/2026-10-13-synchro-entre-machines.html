Synchro entre machines — mise en place

Ce qu'il faut faire une fois chez Google, puis une fois sur chaque machine, pour reprendre sur le mini-PC une conversation commencée sur ce PC, et l'inverse. Version 0.4.0 de docpin.

≈ 10 minchez Google, une seule fois
0 €ton Drive, aucun serveur à tenir
< 1 minpour qu'une session arrive
rienne part d'un dossier non autorisé

1. Chez Google, une seule fois

  1. Créer un projet sur console.cloud.google.com, nommé par exemple docpin, avec ton compte Google personnel.
  2. Activer l'API Google Drive : « APIs & Services », puis « Library », chercher Google Drive API, puis « Enable ».
  3. Écran de consentement (« Google Auth Platform » ou « OAuth consent screen ») : type External, nom docpin, ton adresse comme contact. Dans les scopes, ajouter …/auth/drive.appdata.

    En mode Testing, ajoute-toi comme utilisateur de test : Google fait alors expirer l'autorisation au bout de 7 jours, et il faut recliquer « Connect ». Pour l'éviter, publie l'application (« Publish app ») ; si Google demande une vérification pour ce scope, reste en mode Testing.

  4. Créer le client : « Clients » (ou « Credentials »), puis « Create client », type Desktop app. Note l'ID client et le secret.

    Un client « Desktop » accepte tout retour vers http://127.0.0.1, quel que soit le port : rien d'autre à déclarer.

2. Sur chaque machine

  1. Mettre docpin en 0.4.0 : claude plugin update docpin@docpin. Sur le mini-PC, il faut d'abord WSL, Claude Code dans WSL et le plugin, comme le dit le README.
  2. Ouvrir la page d'accueil (! annotate open), carte Sync between machines. Store : Google Drive. Coller l'ID client et le secret, choisir une phrase secrète (8 caractères au moins), puis « Save ».
  3. « Connect Google Drive » : la page de Google s'ouvre. Comme c'est ton application, Google affiche « Google n'a pas validé cette application » : « Paramètres avancés », puis « Accéder à docpin ». Tu reviens sur la page, « Google Drive connected ».
  4. Autoriser les dossiers dont les sessions peuvent partir, par exemple ~/workspace/misc. Sur ce PC, jamais un dossier de projets d'employeur.
  5. Cocher « Sync on ».

3. Au quotidien

  1. Avant de partir : commiter et pousser. L'envoi avertit s'il reste des fichiers non commités ou des commits non poussés.
  2. « Send a session… » sur la page, ou ! annotate sync send dans la conversation elle-même.
  3. Sur l'autre machine, en moins d'une minute, la session apparaît sous Arrived here. « Pull before resuming » s'affiche si son clone n'est pas au même commit. Fais le git pull, puis « Resume here » : un onglet reprend la conversation et lui dit où elle est maintenant.
  4. Si son clone n'est pas trouvé, la session attend : tape son dossier, « Place here ». La fois suivante, elle y retourne toute seule.
